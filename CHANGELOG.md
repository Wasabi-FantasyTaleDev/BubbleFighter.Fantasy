# Changelog

Dates use `YYYY-MM-DD`; times, when supplied, use Asia/Shanghai (UTC+08:00). Add new entries above older entries and update the Chinese version in the same commit. This public log starts with prerelease preparation; earlier development records are retained privately.

## Unreleased

- 2026-10-27: The store downloads GitHub release attachments and archives through public mirrors when **GitHub mirror acceleration** is on (Manage sources). Automatic mode measures the mirrors before each download and falls back to GitHub; a speed test lists every mirror's rate and latency and can pin one. Release information is never mirrored, and every mirrored byte must match GitHub's published size and SHA-256. A server in mainland China asks the first administrator once whether to turn it on. The list is `data/github-mirrors.json` (`github_mirrors_path`); `use_github_mirror` is removed. Contracts 3.1.0 adds `IDistributionGithubMirror`.
- 2026-10-27: The WebUI manages the running server. The overview console sends commands to the server, toggles maintenance mode (new admissions pause; connected players stay) and restarts the server, reporting success only after it is back with a new start time. Plugins can be loaded, unloaded, disabled and reloaded; rooms show their players and password; client builds can be added and their data imported on the Builds page. Each of these actions has its own permission (`webui.plugins.manage`, `webui.server.maintenance`, `webui.server.restart`, `webui.clients.manage`, `webui.rooms.inspect`); `webui.access` alone only shows the server.
- 2026-10-27: The client plugin policy is edited under Plugins > Client plugin policy. Plugins are added by identity or from the store catalog; each rule has a type, its own client builds and, by type, a version or recommendation sources. A conflicting rule asks which one to keep, a change made elsewhere meanwhile is reported instead of overwritten, and the profile's policy can be restored. The old store policy page is removed.
- 2026-10-27: The account that claims an installation is now the WebUI administrator of the profile it starts. Packaged profiles list no permission subjects, so before this the setup administrator could sign in but use nothing that checks a permission.
- 2026-10-27: Fix client builds after setup. A ready server can add clients at any time, and the Builds page lists a configured client whose data is not imported yet and saves the imported folder so the build starts. A live SQLite installation no longer fails every configuration change by opening its database a second time.
- 2026-10-27: The WebUI console and Logs page show the whole server's log, through a host log feed (`IServerLogFeed`, Abstractions 8.16.0), instead of only the administration listener's own requests; per-request ASP.NET Core lines are no longer logged. Plugins show their identity and declared description, the Built-in and Updates filters work, and fields a plugin does not provide are left out. The overview counts open rooms across every build, and `/api/health` answers without a session. Reloading or unloading a plugin that the administration row depends on no longer freezes the WebUI: the request answers while the row restarts. Client data is no longer offered on the Settings page.
- 2026-10-27: Replace the Launcher's plugin recommendations with a client policy. `launcher.http` now takes `client_policy`: named store sources and, per plugin, typed rules (`require`, `disable`, `recommend` with sources, `min_version`, `max_version`, `latest`), each with its own optional builds. Conflicting rules (for example `disable` with any other rule, `latest` with `max_version`, or a minimum above the maximum on an overlapping build) stop the row with the plugin and rule named. The catalog and sign-in responses send `clientPolicy` instead of `pluginRecommendations`. The WebUI management API moves to `/api/setup/client-policy` with per-plugin and source routes, a rule-type listing for forms, and an `If-Match` revision so two editors cannot overwrite each other; the permission is now `webui.settings.client_policy`.
- 2026-10-27: Remove limits nobody asked for. The client policy has no limit on plugins, rules, sources or builds; the installation settings file has no size or nesting limit; and `launcher.http` no longer caps the number of images, whitelist names or instances, text and address lengths, or the upper values of its tunables (for example `ticket_seconds` above ten minutes). Values must still be valid, and the listener's request-size and rate settings remain configurable. The default `minimum_password_length` is now 6, which is also the lowest allowed value, and passwords have no upper length.
- Upgrading: `plugin_recommendations` is removed; move its entries to `client_policy` or startup fails on the unknown key. The routes `/api/setup/client-plugins` and the permission `webui.settings.client_plugins` are removed. Contracts 3.0.0: `ClientPluginPolicy`, `ClientPluginPolicyRules` and `InstallationClientPluginSettings` are replaced by `ClientPolicy`, `ClientPolicyRules` and `InstallationClientPolicySettings`.
- 2026-10-27: WebUI plugins default to a compact browser with a separately scrolling detail pane. Operators can search, filter by state and switch back to the detailed table; the chosen layout is remembered in the browser. Local frontend development can target a separate backend with `BFF_WEBUI_BACKEND`.
